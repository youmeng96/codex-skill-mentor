# Skill 评审表

总分 100 分。评审时先给总分，再只列最关键的 1–3 个问题和可直接采用的修复。

## 1. 触发与发现（20 分）

- [ ] 名称是 lowercase-hyphen-case，且与目录一致。
- [ ] description 说明了能力和适用场景。
- [ ] 描述包含足够区分度，不是万能触发词。
- [ ] 需要排除的相邻场景有明确边界。
- [ ] 用户能自然说出至少两个应触发请求。

## 2. 范围与目标（15 分）

- [ ] 解决一个足够窄、可重复的真实任务。
- [ ] 目标用户和输入输出明确。
- [ ] 有可观察的成功标准。
- [ ] 没有把项目约定或一次性提示误做成 Skill。

## 3. 指令可执行性（25 分）

- [ ] 工作流能由另一个 Codex 实例直接执行。
- [ ] 指令之间有明确顺序或条件，不互相冲突。
- [ ] 包含必要的停止条件、失败处理和授权边界。
- [ ] 没有重复系统政策、通用编程常识或空泛建议。
- [ ] 关键术语和输出格式没有歧义。

## 4. 渐进披露与资源（15 分）

- [ ] `SKILL.md` 保留高频、共性、会改变决策的内容。
- [ ] 条件性细节放入 `references/`。
- [ ] 重复逻辑有脚本时才使用 `scripts/`。
- [ ] 固定模板或素材有明确用途时才使用 `assets/`。
- [ ] 没有未使用的目录、占位文件或过早抽象。

## 5. 验证与测试（15 分）

- [ ] 通过结构验证。
- [ ] 至少三个真实请求覆盖成功、相邻误触发和边界停止。
- [ ] 测试没有向执行者泄露预期答案。
- [ ] 修复由实际失败驱动，而不是猜测。
- [ ] 结果可观察、可复现。

## 6. 发布准备度（10 分）

- [ ] README 包含安装、快速开始、示例和限制。
- [ ] 有许可证和第三方归属。
- [ ] 有版本号与 CHANGELOG。
- [ ] CI 可重复运行。
- [ ] 在干净环境中安装成功。

## 评分解释

- 90–100：可以发布并持续迭代。
- 75–89：可用，但应先修复最关键的触发、执行或验证问题。
- 60–74：原型，不建议公开宣称稳定。
- 0–59：重新缩小范围，回到最小可运行版本。
