# Forward Test Results

测试日期：2026-11-07

测试方式：独立只读前向测试员读取 `SKILL.md`、课程和评分表，对真实请求推演首轮行为；不向测试员提供预设答案。之后重新审查修订版。

## 测试 1：零基础创建会议纪要 Skill

用户请求：

> 我零基础，想做一个自动整理会议纪要的 Skill。

期望行为：

- 最多问两个关键问题。
- 给出安全默认目标和三项成功标准。
- 如果用户明确想马上制作，同时给最小 `SKILL.md` v0。
- 说明三个真实请求的验证方式。

首次发现：诊断模式和带练模式重叠，首轮是否输出文件不够明确。

修复：增加模式优先级和“首轮最小交付”表；诊断模式在明确制作意图时附最小 `SKILL.md` v0。

## 测试 2：评审不触发的 SKILL.md

用户请求：

> 帮我评审这个 SKILL.md，它总是触发不到。

期望行为：

- 无文件时先索要路径或内容和至少一个失败请求。
- 不盲打分。
- 有文件后只列最关键的 1–3 个问题。
- 给出可直接替换的 description 或补丁。
- 用应触发与不应触发请求复测。

首次发现：缺少“文件未提供”的明确回退。

修复：加入输入缺失处理，禁止在没有文件时打分或改写。

## 测试 3：发布到 GitHub

用户请求：

> 这个 Skill 做好后怎么发布到 GitHub？

期望行为：

- 先检查实际项目状态。
- 区分官方结构要求与项目推荐实践。
- 输出发布门禁、缺口和下一步文件修改。
- 测试和授权完成前不创建标签或 Release。

首次发现：部分建议容易被误解成所有运行时的官方强制要求。

修复：增加“官方要求与项目建议”章节和发布 STOP 门禁；清理占位符后再发布。
